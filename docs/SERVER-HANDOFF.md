# Перенос Repo Anti-Rot на сервер

Домен: **repo-janitor.app**. Целевая система: Windows, Docker Desktop с Linux-контейнерами / WSL 2.
Ветка с подготовкой публичной беты: `codex/public-beta-self-hosting`.

## Забрать проект

```powershell
git clone --branch codex/public-beta-self-hosting https://github.com/YpCIIIaK/repo-janitor.git
cd repo-janitor
node scripts/setup-local.mjs
```

Нужен Node.js 22+ для команд подготовки. Заполнить `.env.local`: GitHub API token,
при необходимости GitHub OAuth, OpenRouter и Resend. Файл не попадает в Git или
Docker-образ. Внутренние секреты генерируются автоматически.

Если нужны существующие данные, перенести их отдельно по инструкции
[SELF-HOSTING.md](SELF-HOSTING.md). Новый clone не переносит ни базу Render/Supabase,
ни локальные Docker volumes, ни отчёты из браузера. Для сохранения действующих
сессий и интеграций потребуется безопасно перенести соответствующие секреты.

## Сначала локальная проверка

```powershell
docker compose --env-file .env.local up -d --build
node scripts/smoke-local.mjs
docker compose --env-file .env.local ps
```

Приложение доступно на `http://localhost:3000`. Проверить настоящий скан, историю,
три одновременных задания, отмену, очередь и отзывчивость `/api/health`. Во время
нагрузки смотреть `docker stats`, использование RAM/CPU и свободного диска Windows.
Подобрать ограничения под это устройство; характеристики другой машины не являются
доказательством достаточной производительности сервера.

## Затем домен

Настроить DNS и доступ TCP 80/443 к серверу. Удалить неверную AAAA-запись, если IPv6
фактически не обслуживается. Проверить отсутствие CGNAT или подготовить подходящий
туннель с корректным доверием к прокси.

```powershell
node scripts/configure-domain.mjs repo-janitor.app
docker compose --env-file .env.local --profile public up -d
```

Команда меняет только DOMAIN и два публичных URL, сохраняя ключи. Проверить HTTPS
на `https://repo-janitor.app` из внешней сети, сертификат и перенаправление HTTP.
OAuth callback: `https://repo-janitor.app/api/auth/github/callback`.

## Перед открытием пользователям

- Проверить OAuth, подписку на собственный подтверждённый email и доставку письма.
- Проверить ИИ после настройки модели/ключа и лимита расходов у провайдера.
- Создать резервную копию и восстановить её в отдельный volume по инструкции.
- Перезапустить приложение, затем Windows: проверить автозапуск Docker, HTTPS,
  сохранность данных и работу фонового обслуживания. Отключить сон сервера.
- Скопировать резервные копии на другое устройство.
- Переключать Render и публичные ссылки после успешной проверки переноса.

Публичная бета использует один процесс приложения. Очередь ограничена, но задания
не восстанавливаются после перезапуска. ИИ предлагает рекомендации; автоматическое
создание проверенных PR, GitHub App и рабочие пространства команд — следующие этапы.
Исследование конкурентов и критерии дальнейшего развития: [COMPETITIVE-REVIEW.md](COMPETITIVE-REVIEW.md).
