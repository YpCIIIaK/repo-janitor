# Локальный рескан через существующий сайт

Дашборд: **`http://127.0.0.1:3100/local-rescan`**.
В локальном режиме ссылка также появляется в шапке `/state`.
На обычном публичном запуске страница и `/api/local-rescan` возвращают 404.

## Первый запуск

Нужны Node.js 22+, pnpm, Git и `tar`. На Windows подойдёт системный `tar.exe`.
Команды одинаковы для PowerShell, macOS и Linux:

До слияния PR #20 используйте ветку `bench/2026-11-16-1`:

```sh
git fetch origin
git switch bench/2026-11-16-1
git pull --ff-only
```

```sh
pnpm install --frozen-lockfile
pnpm run build:packages
pnpm local:rescan restore
pnpm local:dashboard
```

`restore` загружает последний зафиксированный полный набор этого цикла:
`bench-data-2026-11-15-1`, 10 000 проектов / 10 007 записей. Он проверяет
SHA-256 архивов, сохраняет их коммит и распаковывает данные в
`benchmark/.local-rescans/baseline/`. Существующие `benchmark/.results/`
и другие готовые результаты не изменяются. Если данные уже есть в обычных
benchmark-каталогах, восстанавливать архив необязательно: они имеют приоритет.
После прерванного восстановления повторите ту же команду.

Другой опубликованный набор с SHA-256-манифестом можно указать явно:

```sh
pnpm local:rescan restore bench-data-2026-11-15-1
```

Восстановление и сканирование не выполняются одновременно. Уже установленный
baseline другого коммита не заменяется автоматически: сначала сохраните или
переместите каталог `benchmark/.local-rescans/baseline/`.

Для другого порта: `pnpm local:dashboard 3200`.
Лаунчер сам включает локальные функции и привязывает сервер к `127.0.0.1`.
Не включайте `REPO_JANITOR_LOCAL_RESCAN` на публичном сервере и не меняйте
привязку на `0.0.0.0`. Обычный `pnpm dev` локальные функции не включает.

## Что выбирать в форме

В поле **Исходные результаты** можно выбрать опубликованный набор или любой
успешно завершённый локальный запуск. Для отсутствующих в нём репозиториев
используется обычный baseline. Прошлый запуск остаётся неизменным.

- **Весь корпус** — все закреплённые записи из `benchmark/corpus.json`,
  включая исторические псевдонимы; это не новые 10 007 уникальных проектов.
- **Только уже просканированные** — записи с сохранёнными результатами.
- **Выбрать репозитории** — поиск, отдельные галочки и выбор всей найденной
  группы. В списке отображаются первые 150 совпадений; уточните поиск для остальных.
- **Импортировать JSON** — любой свой список публичных репозиториев GitHub
  с полными SHA. Например, можно отдельно загрузить прежний список Казахстана.

```json
[
  {
    "name": "owner-project",
    "url": "https://github.com/<owner>/<project>",
    "sha": "0123456789abcdef0123456789abcdef01234567"
  }
]
```

Без полного SHA запуск отклоняется: ветка `main` не фиксирует состояние кода.

Режимы:

- **Только изменившиеся сканеры** — обычный resumable benchmark. Сравнивает
  SHA и отпечатки правил с исходными результатами. Подходящие результаты
  используются повторно; отсутствующие снимки сканируются с нуля.
- **Полный офлайн-рескан + история git** — запускает все локальные проверки
  заново и читает полную историю. Этот режим существенно тяжелее.
- **Отдельные сканеры** — принудительно повторяет выбранные проверки;
  сохраняет результаты остальных проверок в отдельной рабочей копии.

По умолчанию **4 рабочих процесса**, доступно 1–32. Каждый обслуживает один
репозиторий за раз. Можно настроить резерв свободного диска и таймаут одного
этапа. При недостатке места очередь приостанавливается, а не объявляет
неполный скан успешным. Стандартный лимит benchmark на размер клона — 2000 МБ —
не увеличивается. Для большого корпуса с четырьмя процессами разумно иметь
не менее 20 ГБ свободного места; расход зависит от выбранных репозиториев.

**Обновить OSV и метаданные лицензий** — отдельный сетевой этап с аудитом
транспорта. Он выполняется после офлайн-проверки каждого репозитория.
Офлайн-отчёт и сетевой снимок скачиваются отдельными кнопками. Без этого
переключателя нет заявления о свежей проверке внешних баз.

## Прогресс, пауза и продолжение

Дашборд показывает очередь, активные задачи, завершения, ошибки, свободный
диск, приблизительное оставшееся время, логи и JSON-отчёты.

- **Пауза после текущих задач** даёт работающим проверкам закончить.
- **Остановить сейчас** завершает процессы задач и их дочерние процессы Git.
- **Продолжить** возвращает незавершённые задачи в очередь, сохраняя успехи.
- **Повторить ошибки** добавляет в очередь только неудачные задачи.

Закрытие вкладки не останавливает worker. После перезапуска веб-сервера
откройте ту же страницу. После выключения компьютера нажмите «Продолжить».
Одновременно выполняется один запуск; внутри него — выбранное число процессов.

Каждый запуск получает собственный UUID и каталог:

```text
benchmark/.local-rescans/<UUID>/
  plan.json                    # настройки и SHA репозиториев
  state.json                   # прогресс и счётчики
  tasks/<repo>.json            # состояние конкретной задачи
  logs/<repo>.log              # логи
  workspace/                   # зафиксированный код и отдельные данные
    ready.json                 # отпечаток версии сканера
    packages/{core,cli}/        # копии исходников и собранного сканера
    benchmark/.results/        # новые результаты
    benchmark/.inventory/
    benchmark/.history/
    benchmark/.gitlog/
```

Успешные результаты не перезаписывают исходный benchmark и не публикуются
автоматически. Не удаляйте каталог запуска до сохранения его результатов.
Клоны задач удаляются после обработки. Весь `.local-rescans/` исключён из Git,
проверок TypeScript, линтера и трассировки production-сборки сайта.

Исходники и сборки сканера фиксируются при подготовке запуска. Продолжение и
повторы используют **ту же** версию: после улучшения правил создайте новый
запуск. Установленные зависимости используются из локального pnpm-хранилища;
не переустанавливайте и не очищайте их во время проверки.

## Работа без браузера

```sh
pnpm local:rescan run
pnpm local:rescan run local-config.json
pnpm local:rescan status
pnpm local:rescan status UUID
pnpm local:rescan pause UUID
pnpm local:rescan resume UUID
pnpm local:rescan retry UUID
pnpm local:rescan cancel UUID
pnpm local:rescan export UUID
```

Пример `local-config.json`:

```json
{
  "names": ["express", "zod"],
  "mode": "changed",
  "jobs": 4,
  "minFreeGiB": 2,
  "timeoutMinutes": 30,
  "refreshMetadata": false
}
```

Без `names` выбирается весь корпус. Вместо `names` можно передать `targets`
с массивом закреплённых записей. Для `mode: "scanners"` добавьте `scanners`,
например `["insecure-code", "commented-code"]`.
Для исходных данных из прошлого запуска добавьте `"baselineRun": "UUID"`.
Выборочная проверка обновляет отпечатки только выбранных сканеров; остальные
не объявляются актуальными без проверки.

## Как использовать готовый локальный пересчёт

Сначала проверьте счётчики: `completed_with_errors`, `paused`, `interrupted`
и `cancelled` не означают полный успех. Сохраните каталог `workspace/benchmark`
вместе с `ready.json` и `plan.json`: это данные, версия сканера и точные SHA.
Не объединяйте результаты разных версий вручную.

`pnpm local:rescan export UUID` упаковывает только полностью успешный запуск
в `benchmark/.local-rescans/UUID/results.tar.gz` и создаёт SHA-256 рядом.
В архив входят результаты, настройки, точные SHA, версия сканера и его
калибровка. Клоны, зависимости, `.env` и исходники целевых приложений туда
не включаются. Этот файл удобно передать для дальнейшей проверки.

Перед заменой опубликованного набора выполните контроль сохранения TP,
проверку исходного baseline, калибровку, обновление статистики и упаковку из
[ROUTINE.md](ROUTINE.md). Локальный менеджер не снимает эти проверки и не
продвигает данные в `bench-data` автоматически. Его `workspace` — рабочая
песочница, а не отдельный Git checkout: проверяйте и публикуйте данные из
полного checkout соответствующей версии проекта, не запускайте `archive push`
внутри песочницы.
