# Repo Anti-Rot — план роста (v3)

Продолжение PLAN.md v2. Фаза A закрыта (проверено на `de43bad`: 467 тестов зелёные,
догфуд C/67, severity калибруется по графу лока). Этот документ — про то, чем
цеплять человека, и про идентичность, без которой не работает мониторинг.

---

## 0. Главная мысль

У проекта 467 тестов и ноль внешних пользователей. Ещё один сканер этого не меняет.

Не хватает **не фичи, а причины вернуться**. Разовый скан её не создаёт: человек
посмотрел грейд и закрыл вкладку. Лимиты и тиры это не лечат — нечего лимитировать,
если возвращаться незачем.

Причина вернуться уже построена и не подана: **History tab даёт временной ряд.**
Никто на рынке не мерит распад репозитория во времени. Из этого делается крючок:

> Оценка твоей репы упала с C на D за 3 недели. Вот 4 коммита, которые её уронили.

Всё остальное в этом плане — обслуживание этой одной фразы.

## 2. Крючок

### 2.1 Перцентиль вместо счётчика (S) ⭐ самое дешёвое

Счётчик «просканировано 1 240 реп, найдено 8 400 уязвимостей» не цепляет никого:
это про тебя, а человеку интересен он сам. И на старте играет против — маленькие
числа кричат «тут пусто».

Та же данность, развёрнутая на пользователя:

> **Твоя репа: 67/100. Хуже, чем 71% просканированных.**

- [ ] Агрегировать анонимную статистику своих сканов (score, grade, язык, размер)
- [ ] Считать перцентиль, показывать в отчёте первой строкой
- [ ] Разрезы по языку и размеру — «хуже 71% TS-реп сравнимого размера» весомее общего

Данные нужны те же, что ты хотел собирать. Разница только в подаче: не сумма, а позиция.

### 2.2 Скан чужой репы (M) ⭐ делать вперёд всего остального

Публично, без аккаунта, по любому URL.

Меняет мотивацию с «проверь себя» (неприятно, защитная реакция) на «посмотри на них»
(весело, шарится). Люди сканируют конкурентов, зависимости перед тем как взять,
репу которую покупают, известные проекты ради лулзов.

- [ ] Лендинг с одним полем ввода; дашборд уезжает на `/app`
- [ ] `/r/<owner>/<name>` — статичный расшариваемый отчёт
- [ ] OG-картинка с грейдом: репа с `F` в чужой ленте — это клик
- [ ] Лимиты: размер клона (кап есть, `e059c2d`), таймаут, очередь, конкурентность
- [ ] Хостинг Railway / Fly / Hetzner — клон репы под serverless-таймаут не лезет

Приманка уже построена — дерево коммитов, badge, грейд — и ни к чему не прицеплена.
Вот это прицепляет.

### 2.3 Недельное письмо о падении (M)

- [ ] Cron: пересканить подписанные репы, сравнить с прошлым чекпоинтом
- [ ] Письмо только при значимом изменении. Тишина, когда всё стабильно — иначе отписки
- [ ] В письме: было → стало, и **какие коммиты уронили оценку**. Конкретика, не «-4 балла»
- [ ] Ссылка на полный дифф отчётов

Это единственная модель, где ежемесячный платёж логичен: за разовый скан платят
один раз, и правильно. За слежку платят ежемесячно.

## 3. Идентичность: три уровня, а не один

Для мониторинга идентичность нужна — но «идентичность» и «аккаунт» не одно и то же,
и разница в конверсии огромная.

**Правило: сначала ценность, потом идентичность.** Экран регистрации на входе убивает
крючок из §2.2 — человек пришёл посмотреть чужой грейд ради интереса, и уйдёт. Email-поле
*после* того, как он увидел падающую оценку, — предложение в момент максимальной мотивации.

### Уровень 0 — чекпоинты в самой репе (готово)

Action пишет отчёты, `/api/reports` их отдаёт. Для CI аккаунт не нужен: репа сама себе
идентификатор, история в артефактах, дельта против прошлого прогона. Построено, но не
подано как фича.

- [ ] Описать этот сценарий в README как «мониторинг без регистрации»

### Уровень 1 — только email, без пароля (S–M) ⭐

> Оценка упала? Пришлём письмо. `[email]` `[Следить]`

Ни пароля, ни подтверждения, ни экрана регистрации. Отписка ссылкой в письме,
magic link для управления. **Это не аккаунт, это подписка на репу.**

Ключевое: чекпоинты для публичной репы считаются **и без email**. Скан привязан к
`owner/name`, история хранится по репе, а не по человеку. Перцентиль, тренд и падение
доступны с первого дня для всех, кто хоть раз сканировал — email нужен только чтобы
доставить уведомление, а не чтобы хранить данные.

- [ ] Таблица `subscriptions`: email, repo, частота, токен отписки
- [ ] Cron. SQLite или Postgres на том же хосте — просто таблица, не Better Auth с ролями и организациями
- [ ] Magic link на страницу «мои подписки»

**Побочный эффект — бесплатный рыночный сигнал.** Из 100 увидевших грейд адрес оставили
трое → мониторинг никому не нужен, и хорошо, что узнал за день, а не за месяц разработки
GitHub App. Тридцать → строй уровень 2 немедленно. Это честнее прохождение контрольной
точки на 50–100 людей, чем «показать кому-нибудь».

### Уровень 2 — GitHub App, только для приватных реп (L)

Здесь идентичность неизбежна — нужен токен. И пароля не должно быть тем более:
**GitHub App, а не свой логин.** Человек жмёт Install, выбирает репы, всё.

GitHub App даёт то, чего OAuth не даёт: webhook на push, установочный токен с узкой
областью, чек-раны прямо в PR.

- [ ] Установки, шифрование токенов, вебхуки
- [ ] Чек-ран на PR с дельтой оценки

> Делать, когда кто-то попросит приватную репу. Не раньше.

### Что гейтить

Гейт по количеству на девтуле не работает: разработчик упирается в лимит и селф-хостит —
MIT и Docker ты вручил сам. Гейтить то, что нельзя воспроизвести локально:

| Работает (не форкается) | Не работает (форкается за вечер) |
|---|---|
| приватные репы — нужен твой OAuth | «10 сканов в месяц» |
| мониторинг и алерты — нужен твой cron | «глубина истории» |
| перцентиль — нужна твоя база | «больше сканеров» |
| PDF-отчёт для сделки | «быстрее очередь» |

## 4. Новые сканеры

Не «ещё сигналы», а те, что усиливают позиционирование под покупателя кода.

Сделано (четвёрка, согласованная отдельно от списка ниже):

- [x] **`workflow-security`** — права `GITHUB_TOKEN`, `pull_request_target` с чекаутом чужого кода, инъекция в `run:`, экшены на изменяемых тегах
- [x] **`eol-runtime`** — Node / Python / образы раннеров, снятые с поддержки. Таблица зашита, неизвестная версия = молчание
- [x] **`docs-drift`** — README против репозитория: несуществующий скрипт, бейдж на отсутствующий воркфлоу, чужой менеджер пакетов
- [x] **`config-conflict`** — два конфига на одну вещь, один из которых молча игнорируется (`.eslintrc` рядом с flat-конфигом, ключ в `package.json` рядом с выделенным файлом, брошенный CI-провайдер) плюс два локфайла в одной директории. Проверено на 14 живых репозиториях: 0 ложных срабатываний, каждый отсеянный класс закреплён тестом с именем проекта, который его дал

Осталось:

- [x] **Лицензии** (`license-risk`) — лицензии прямых зависимостей против лицензии самого проекта. AGPL/SSPL в рантайм-зависимости — critical, GPL — warning, LGPL/MPL — info; copyleft-проект не получает copyleft-находок вовсе. Проверено на 2778 установленных пакетах: единственный промах (CC-BY-4.0) закрыт
- [ ] **Onboarding friction** (M) — может ли новый человек это запустить? Нет README-шагов, нет `.env.example`, скрипты падают, недокументированные зависимости от внешних сервисов. Для покупателя вопрос №1 после «что внутри», и метрики такой нет ни у кого
- [ ] **Copy-paste / дублирование** (M) — классический сигнал энтропии, идеально ложится на временную ось: дублирование, растущее от квартала к кварталу, — это распад в чистом виде
- [x] **CI/CD health** (`ci-health`) — не «есть ли CI», а проверяется ли хоть что-нибудь: `continue-on-error`, `if: false`, `|| true` на тестовой команде, тесты есть но ни один воркфлоу их не гоняет, нет триггера на `pull_request`. Молчит там, где не уверен: чужой CI-провайдер (nest гоняет весь сьют на CircleCI), воркфлоу без триггера на изменение, шаги-регенераторы фикстур, `continue-on-error` на кэше. Три класса ложных срабатываний сняты догфудом на pnpm, nest и babel
- [ ] **Abandonment score по репе** (M) — частота коммитов, живые контрибьюторы, время жизни issue. «Насколько живой проект» — вопрос №1 покупателя
- [ ] **Стоимость гнили в часах** (S) — каждая находка → оценка времени, суммируется: «технический долг ~34 часа». Нетехнический покупатель понимает часы, не понимает `warning: 6`
- [ ] **Прогноз тренда** (S) — «при текущей динамике через 6 месяцев grade D»
- [ ] **`--fix` в CLI** (M) — снести закомментированный код, удалить merged-ветки, дописать `.env.example`. Превращает линтер в инструмент

**Не делать:** ничего вокруг секретов и CVE. Паритет с бесплатным достигнут, глубже — сжигание времени.
