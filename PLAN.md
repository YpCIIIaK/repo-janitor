## 1. Блокеры: сломано или врёт документация

Это чинится первым, до любой новой фичи.

### 1.1 `/api/reports` не существует — CI→дашборд разорван 🔴

Роут отсутствует. `app/api/` содержит только `ai/complete`, `badge/[owner]/[name]`, `ingest`, `scan`, `scan/history`.

При этом на `/api/reports` ходят трое:

| Кто | Файл | Что ломается |
|---|---|---|
| Дашборд | `components/repo-anti-rot/server-sync.tsx:14` | отчёты из CI никогда не подтягиваются в браузер — тихий 404 |
| Action | `packages/action/src/index.ts:105` через `reportsEndpoint()` | дельта в PR-комменте не считается против прошлого скана |
| README | `README.md:351` | документирует `GET /api/reports` и `REPO_ANTI_ROT_READ_TOKEN` |

`REPO_ANTI_ROT_READ_TOKEN` не встречается в коде вообще — только в двух README. То есть описанная в README таблица «Security & hardening» частично документирует несуществующее.

**Сделать:** `app/api/reports/route.ts` — `GET`, читает `readServerRepos()`, гейтится `checkBearer(request, process.env.REPO_ANTI_ROT_READ_TOKEN)`. Тест на 401 при выставленном токене и на 200 при пустом сторе.

Отдельно: `ingestEndpoint` и `reportsEndpoint` живут рядом в `packages/action/src/lib.ts` и покрыты тестами — тесты проверяют форму URL, но не то, что эндпоинт существует. Добавь смоук: Action против поднятого дашборда.

### 1.2 `package.json` называется `my-project`

```json
{ "name": "my-project", "version": "0.1.0", "private": true }
```

Первое, что открывает человек, оценивающий проект. Плюс `next.config.mjs` держит `images: { unoptimized: true }` — след v0/Vercel-скаффолда, который тебе больше не нужен.

### 1.3 CLI не опубликован, версия `0.0.0`

README предлагает `node packages/cli/dist/index.js scan --path .` — то есть склонировать монорепу, поставить pnpm, собрать CLI, и только потом попробовать. Это отсекает 95% людей, которые могли бы просто набрать `npx`.

**Сделать:** опубликовать `repo-anti-rot` в npm (без скоупа — скоуп `@repo-anti-rot/cli` для CLI лишний), `npx repo-anti-rot scan .` как первая команда в README.

### 1.4 `ROADMAP.md` протух и противоречит README

Он говорит: *«одан реальный сканер (`env-lifecycle`), снапшот 2026-06»*, и предлагает как будущую работу A1–A5, B1–B5, C1–C5, E1–E4 — почти всё из этого уже сделано. Твой же `broken-doc-links`/`project-hygiene` в идеале должен ловить такое.

**Сделать:** либо удалить, либо переписать в «что сделано / что дальше». Протухший роадмап в публичной репе читается как «проект брошен».

### 1.5 Репозиторий не оформлен

Нет description, нет topics, нет website, 1 звезда, 0 форков. Никакого демо. Человек, пришедший по ссылке, не понимает за 5 секунд, что это.

## 2. Главное: позиционирование

Здесь я скажу неприятное, потому что это важнее всех фич.

### Проблема

Ты вложил больше всего сил в две вещи, которые уже бесплатны у GitHub:

- **секреты** — GitHub secret scanning, бесплатно на публичных репах, push protection на приватных;
- **уязвимые зависимости** — Dependabot, бесплатно везде, плюс Snyk/Renovate/`npm audit`.

Это самый коммодитизированный слой рынка. Конкурировать там соло невозможно и не нужно.

А то, что действительно уникально, спрятано глубже:

- **age-сигналы** — TODO, ранжированные по `git blame`;
- **bus-factor** — риск «один человек знает этот файл»;
- **dead code / commented-code / skipped tests** — накопленная энтропия;
- **stale branches**, **repo bloat**, **lockfile drift**;
- **History tab** — здоровье репы по коммитам во времени, с `+добавлено / −починено`;
- **hotspot files** — где гниль концентрируется;
- **оценка A–F** одним числом.

**Никто не измеряет распад репозитория во времени.** Все меряют уязвимости в моменте. Вот твой единственный настоящий эдж, и он сейчас — четвёртая вкладка.

### Кто за это платит

Не разработчик. Разработчик форкнет и селф-хостнет — мы это уже обсуждали. Платит тот, у кого есть **решение и деньги в движении**:

**1. Тот, кто покупает или наследует чужой код.** Это killer use case, и он прямо смыкается с нашим прошлым разговором про Acquire / microns / Flippa. Человек покупает микро-SaaS за $3–50K и понятия не имеет, что внутри. Твоя History-вкладка + bus-factor + hotspots + grade — это буквально готовый **отчёт code due diligence**, и такого инструмента на рынке нет. Ни один покупатель на microns не запускает Snyk; он смотрит на код глазами полчаса и молится.

**2. Агентства, принимающие чужой проект на поддержку.** Тот же сценарий, регулярный, с бюджетом.

**3. CTO, выбивающий бюджет на рефакторинг у нетехнического руководства.** Оценка A–F и executive summary существуют ровно для этого разговора.

### Что это меняет технически

Огромное упрощение. **Тебе не нужны Postgres, Better Auth, Drizzle и командные аккаунты.** Отчёт «по одной репе, один раз, заплатил — получил» не требует ни аутентификации, ни мультитенантности. Ты выбрасываешь самый тяжёлый кусок будущей работы и одновременно попадаешь в паттерн «бесплатный диагност → платное лечение».

Сейчас персистентность — localStorage на клиенте плюс один JSON-файл `.repo-anti-rot/reports.json` на сервере. Для одноразовых отчётов этого почти достаточно.

## 3. Функциональный план

Отсортирован по «impact ÷ effort» под позиционирование из п.2.

### Фаза A — привести в порядок (S, 1–2 дня)

- [ ] `app/api/reports/route.ts` + тест (§1.1)
- [ ] Переименовать пакет, вычистить `unoptimized: true` (§1.2)
- [ ] Опубликовать CLI в npm, `npx repo-anti-rot scan .` первой строкой README (§1.3)
- [ ] Переписать/удалить ROADMAP (§1.4)
- [ ] Description + topics + demo-ссылка на репе (§1.5)

### Фаза B — публичный диагност (M, 3–5 дней) ⭐ главное

Публичная страница: вставил URL репы → через 30 секунд видишь оценку и топ проблем. Без регистрации, без клона, без сборки.

- [ ] `app/page.tsx` сейчас сам дашборд. Нужен реальный лендинг с одним полем ввода. Дашборд уезжает на `/app`.
- [ ] Хостнуть демо (Railway / Fly / Hetzner — ты уже решил, что не Vercel; для этого сценария особенно, т.к. клон репы под serverless-таймаут не лезет).
- [ ] Жёсткие лимиты на публичном скане: размер клона (кап уже есть — `e059c2d`), таймаут, очередь, конкурентность. SSRF-фильтр у тебя хороший, это уже закрыто.
- [ ] Публичная шара результата: `/r/<owner>/<name>` со статичным отчётом. Это твой виральный крючок — люди будут кидать ссылки друг другу, а не скриншоты.
- [ ] Open Graph-картинка с оценкой. Репа с грейдом `F` в ленте — это клик.

**Стена платного здесь:** бесплатно — оценка, разбивка по категориям, топ-5 проблем. Платно — полный список находок, History-дерево, экспорт.

### Фаза C — Due Diligence Report (M–L, 5–8 дней) ⭐ то, что продаётся

Один PDF/HTML-документ по одной репе. Разово, $49–149, без подписки и без аккаунта.

Содержимое собирается почти целиком из того, что у тебя уже есть:

- обложка: grade, score, issue density, LOC, языки (`About` tab уже это считает);
- **траектория здоровья** — график из History tab: улучшается репа или гниёт. Это то, за что платят, и этого нет ни у кого;
- **риск людей** — bus-factor: какие файлы знает один человек;
- **hotspots** — где сконцентрирована гниль, с оценкой стоимости;
- security: секреты в истории + CVE (тут ты не уникален, но в отчёте это обязательный раздел);
- «что чинить первым» — executive summary, у тебя уже реализован;
- приложение: полный список находок.

Технически нужно: PDF-рендер отчёта, оплата (для Казахстана — Paddle или LemonSqueezy как merchant of record, чтобы не воевать со Stripe и налогами), и очередь на длинный скан истории.

> Не начинай Фазу C, пока Фаза B не приведёт первых людей. Сначала подтверди, что кто-то вообще жмёт «полный отчёт».

### Фаза D — то, чего не хватает движку

Отсортировано по ценности для позиционирования, а не по красоте:

- [ ] **Оценка стоимости гнили в часах.** Каждая находка → грубая оценка времени на починку, суммируется. «Технический долг: ~34 часа». Нетехнический покупатель понимает часы, не понимает `warning: 47`. Это самая дешёвая фича с самым большим эффектом на продажу.
- [ ] **Сравнение с бенчмарком.** «Score 62 — это хуже, чем 78% отсканированных репозиториев». Требует агрегировать анонимную статистику своих же сканов. Даёт и продукту вес, и тебе датасет.
- [ ] **Прогноз тренда.** History уже даёт временной ряд — «при текущей динамике через 6 месяцев grade D». Пугает ровно правильно.
- [ ] **`--fix` в CLI** для механических вещей: удалить закомментированный код, снести merged-ветки, обновить `.env.example`. Превращает линтер в инструмент.
- [ ] **Licence scanner.** Для due diligence — критично: GPL в зависимостях коммерческого продукта убивает сделку. У тебя уже разобраны манифесты всех шести экосистем, данные о лицензиях лежат рядом. Дёшево и прямо в цель.
- [ ] **Abandonment score по репе целиком** — частота коммитов, число активных контрибьюторов, время жизни issue. «Насколько живой этот проект» — вопрос №1 покупателя.

Чего **не** делать: не углублять секреты и CVE. Там ты уже на паритете с бесплатными инструментами, и дальше — сжигание времени.

## 4. Дистрибуция

Порядок важен: это делается после Фазы B, не раньше.

1. **Отсканировать 500 популярных опенсорс-реп и опубликовать рейтинг.** «Health-рейтинг топ-500 npm-пакетов». Это контент, который расходится сам, и он одновременно — твой бенчмарк из Фазы D. Осторожно с тоном: не «этот проект дерьмо», а «вот распределение, вот медиана». Иначе получишь мейнтейнеров во врагах.
2. **Badge.** Он у тебя уже есть, но никто его не носит. Badge в чужом README — бесплатный постоянный трафик. Раздавай его агрессивно, начиная со своих же реп.
3. **Show HN / r/programming.** Заголовок про распад и оценку, не про «ещё один сканер».
4. **Прицельно туда, где покупают код:** сабреддиты и дискорды вокруг микро-приобретений, комьюнити microns. Там твой отчёт — не «ещё один линтер», а недостающий шаг в сделке.
